# Task 30: Vendor PATCH API

Implemented PATCH `/api/v1/vendors/{vendor_id}` with Huma schema, shared admin authentication, bounded request parsing and sqlc queries. The transaction locks the persisted user before the target vendor, applies only supplied fields, validates and serializes the response before commit, and returns sanitized database errors. Explicit null is retained; non-null database columns reject null and roll back. Unknown fields are ignored. Every PATCH validation error replaces its `input` with `[REDACTED]`, including path and malformed-body errors. This deliberately differs from FastAPI, which echoes invalid input; status, error type, location, and message remain unchanged. The 422 OpenAPI schema specifies the redacted string.

Python accepts an empty name on input, commits it, then fails `VendorOut` response validation. Go returns the corresponding 500 but rolls the transaction back before the invalid value is persisted. This is the requested safety difference.
