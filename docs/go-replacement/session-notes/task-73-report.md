# Task 73: scheduled hosting enforcement

## Implementation

The Go scheduler runs hosting enforcement at 04:00 UTC when the scheduler and Cloudflare provider are configured. The job uses the same PostgreSQL session advisory lock as Python (`crc32("hosting-overdue-enforcement")`), and reports contention explicitly. Eligibility requires an enabled hosting item, an eligible item status, and a non-template OPEN, SENT, or PARTIAL invoice with positive balance and a due date strictly earlier than the scan day after its grace period. A restore requires no open balance. The scan processes items independently and reports suspended, restored and error counts. The provider PATCH uses maintenance content for suspension and live content for restoration, retaining the configured name, type, and proxied setting.

Migrations 00006 and 00007 add a shared per-item lease used by both scheduled enforcement and the existing payment restore consumer. The lease is committed before the provider call, and final state is written in a separate transaction after rechecking the item, target and invoices. The lease stores hashes of the original target configuration and the claimed hosting status, enabled flag and hosting flag; no provider credential is stored. Migration 00007 marks pre-existing uncertain leases for manual review because their pre-call item state cannot be reconstructed. Expired or cancelled calls are treated as uncertain and retried with a PATCH consistent with the current balance. If the balance changes during an accepted request, a durable compensating operation is recorded where the authoritative balance permits it. If a suspension may have occurred but there is an open balance and no invoice remains overdue, the lease is retained for manual review; neither an automatic restoration nor a fresh suspension is safe under the policy. A target/configuration or item-status change during a call, or target drift detected on recovery, retains a manual-review flag and causes an error rather than silently acting on the replacement target. Exact schema admission remains fail-closed, with the migration version and PostgreSQL 16 fingerprint updated together.

Cloudflare calls are at least once. A crash or timeout after provider acceptance can produce a repeated PATCH. There is an unavoidable transient window in which the remote DNS change can precede an invoice/payment or target change and the resulting database recheck; a later scan or the payment restore consumer repairs balance-related divergence when eligibility is unambiguous; otherwise it retains a manual-review flag. An administrator must investigate a manual-review flag when a target or hosting state changed, including the original record; the flag does not itself undo a PATCH against an old record. Compensation depends on a subsequent scheduled run and a working provider. A call that remains in flight longer than the two-minute lease could overlap a retry; the configured Cloudflare HTTP timeout is bounded to at most one minute, but an arbitrary injected provider may violate that bound. These operations are not atomic across PostgreSQL and Cloudflare.

## Limits

The differential matrix does not exhaust all combinations of multiple invoices/items or simultaneous edits. The tests do not contact a live Cloudflare account. Manual-review flags are stored in `hosting_operation_leases`; there is no dedicated UI in this task for resolving them. The tests simulate provider acceptance and crash/lease expiry, but cannot prove exactly-once delivery across an external service. Test-only Python is the actual worker/service against a fake HTTP endpoint, not production workers or databases.

## Consolidated review follow-up

The review findings were first reproduced on real PostgreSQL: grace-day, due-date, and invoice-status edits during a suspended fake PATCH lost uncertainty; expired claims failed to retain review after hosting state changes; and restore completion missed maintenance-content changes. The revised tests exercise all three, plus expired ambiguous suspension and expired restore claims after disabled/cancelled/status edits, including an item already disabled at claim time. They verify that no replacement PATCH is sent and manual review is durable. A separate child process also commits a lease, sends a PATCH to the local fake, and exits without finalizing; after an administrator edit and lease expiry, recovery retains manual review and sends no further PATCH. Separate mutations disabling the ambiguous-state guard, the item-state comparison, and the full restore target comparison each produced the expected test failures; the source was restored after each.

## Provider-error follow-up

An unsuccessful Cloudflare response is treated as uncertain: both suspension and restoration retain the operation lease, target and item-state fingerprints, and immediately due repair state. A timeout or error does not imply that the provider rejected the PATCH. The normal eligibility and drift checks govern any retry; an open but not-overdue balance results in manual review rather than an unsafe action. Cancellation before finalization still leaves the pre-call lease until expiry.

Deterministic loopback fake tests applied the requested DNS content before returning HTTP 500 for each operation. They then extended grace after suspension or finalized an invoice through the real Go endpoint after restoration. Both retained the lease, reported manual review without an extra provider request, and converged with a subsequent safe retry after the balance or eligibility was resolved. An additional fake accepted a suspension before timing out; its lease remained durable and an extended grace period led to review without a repeat call. Independent mutations that restored lease deletion on the first failed suspension or restoration each caused the corresponding test to fail; both source files were restored afterward.
