## Review follow-up: date bounds and OpenAPI

`fxDate` is shared by FX latest reads and FX creation. Numeric Unix timestamps outside years 0 through 9999 now reject with the same tested Pydantic error as Python, and an exact date in year zero rejects with Python's year-zero error; time-of-day errors retain their previous ordering. The valid boundary dates 0001-01-01 and 9999-12-31 remain accepted. Tests call actual FastAPI and Go HTTP against separate databases for above-9999, year-zero, and before-zero dates; they assert the invalid creates leave no GBP rows, and the read differential snapshots the complete FX tables. The create OpenAPI `rate` property now has the Python schema's `anyOf` positive number (`exclusiveMinimum: 0`) or string. DELETE 500 documents both JSON and text/plain; operation-level tests check the exact variants and media types.
