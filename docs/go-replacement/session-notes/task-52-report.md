# Task 52: invoice transitions

The Go routes implement finalize, mark-paid and void with an admin recheck and invoice row lock in a transaction. Serialization happens before commit. JSON null void bodies now match Python's validation category; validation error inputs are redacted, including unrelated submitted fields.

Focused PostgreSQL tests passed (`go test -count=1 ./internal/platform -run 'TestInvoiceTransition'`, 15.336s after all mutations were restored). The Python/Go HTTP differential uses separate disposable databases and exercises 108 combinations of action, six statuses, three balances and template flag, plus missing/invalid IDs and 13 void body cases. It compares decoded responses and snapshots of invoices, invoice lines, payments, journal entries and journal lines; validation input values are intentionally normalized to nil because Go redacts them. It checks no-store. Other checks cover unauthenticated requests, body size/redaction, operation presence in OpenAPI, serialization and database-error rollback, competing finalizations by distinct admins, and a demotion observed waiting on the persisted user lock. Both finalize requests are observed waiting on the invoice lock. Payment-like row updates are held under that lock: finalize sees the updated zero balance and void rejects a newly settled invoice. These simulate a payment transaction rather than calling a payment endpoint; coverage does not establish every possible payload or field-rich response.

Red/restored mutations: removing the DRAFT guard caused the differential to fail; replacing the admin row lock with an unlocked read caused the demotion test to fail waiting for the lock; committing on serialization failure caused the rollback assertion to observe OPEN instead of DRAFT. Replacing the invoice lock with an unlocked read failed the observed-lock assertion. An additional early-commit mutation caused normal finalization to fail. All mutations were restored. A red test exposed a missing-reason body leak before the fix; the focused tests subsequently passed. sqlc v1.29.0 generation succeeded.

Full suite passed with `go test -count=1 ./...` against restored Postgres at port 64392 (platform 360.483s, migrations 36.705s; all packages passed).

## Malformed void JSON follow-up

Added 12 Python-versus-Go HTTP cases for malformed JSON and trailing data: incomplete objects and values, extra text and objects, Unicode position counting, unterminated strings, missing colon/comma, invalid escapes, invalid literals, trailing array commas, and whitespace-only bodies. Compared full validation responses including positions and context; Go returns an empty input object without reflecting submitted values. Both databases' affected invoices retain OPEN and balance 1.0000, and table snapshots still match. Existing OpenAPI 422 response already covers validation errors, so no schema change was required.

The added differential first failed on seven initial cases, then exposed additional syntax cases and whitespace-only input; focused tests passed after corrections (6.840s). Disabling the malformed-JSON guard made the differential fail; the mutation was restored. The final full suite passed (`go test -count=1 ./...`; platform 271.736s, migrations 20.932s; all packages passed).
