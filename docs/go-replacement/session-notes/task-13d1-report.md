# Task 13d1 report

Implemented a pure item update parser in `backend-go/internal/platform/items_update_validation.go`. It preserves top-level field omission, null and values with typed fields; target fields and proxied presence are typed as well. It validates in Python schema field order, uses exact decimal/integer parsing, rejects invalid amounts rather than rounding, and performs no database or provider work. The target's absent proxied value is represented as absent with default true, matching `exclude_unset` while retaining the value needed on insertion.

Additional exotic Pydantic numeric string and number coercions have not been exhaustively compared. No HTTP route was registered.

## Review round 1

`boundedItemRat` now limits input length to 4,096 bytes and exponent magnitude to 1,000 before calling `big.Rat.SetString`. All create and update rational parsing uses it; decimal expansion already has its own smaller exponent bound. This deliberately rejects exceptionally large otherwise valid integers, and extreme numeric values do not allocate in proportion to the exponent.
