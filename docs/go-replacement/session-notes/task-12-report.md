# Task 12 report

Implemented payment posting and reversal in `backend-go/internal/ledger/posting.go`, with SQL in `queries/ledger.sql` and sqlc v1.29.0 generated bindings. No schema or Python changes. Callers supply an existing `pgx.Tx`; both operations use a savepoint and leave the outer transaction to the caller.

Public interfaces: `PostPayment(context.Context, pgx.Tx, PaymentInput) (pgtype.UUID, error)` and `Reverse(context.Context, pgx.Tx, pgtype.UUID, string) (pgtype.UUID, error)`. `PaymentInput` holds payment/invoice IDs, status, currencies, amount, withholding, invoice balance and payment date. Reversal locks the original using `FOR UPDATE`, validates swapped lines, and links it to the new entry. Account codes are 1000, 1100, 1300, 4900 and 5900. FX conversion uses `internal/fx` on the payment date. Same-currency AR base credit is the sum of separately rounded debit bases.

Deliberate improvement: inputs with more than four decimal places are rejected, since PostgreSQL would otherwise round numeric(19,4) silently and alter an amount. Savepoints prevent partial writes even when a caller continues its outer transaction after an error. Ingestion currency safe-stop remains the responsibility of its own layer; this service implements explicitly supported cross-currency settlement.

Real PostgreSQL tests exercise same currency, withholding, fractional base rounding, gain, loss, no plug, missing FX, missing account, non-cleared status, negative withholding, invalid cross balance, overprecision, failure after entry insertion, exact swapped reversal, missing original, unbalanced original, duplicate reversal and concurrent reversal. A side-by-side test runs the Python service and Go service against separate disposable databases for fixed-date same-currency, withholding, gain and loss payments and their reversals. It compares source type and ID, memo (normalizing generated entry IDs), account codes, currency, debit, credit, base amounts and FX rate. Generated IDs and timestamps are inherently different. The comparison exposed and corrected Go memo differences. An explicit post-rollback read confirms the caller rollback leaves no entry or lines. Existing balance tests cover unbalanced base and single-currency entries. The overprecision test was observed failing before the guard was implemented; the initial posting test failed to compile before implementation.

Targeted temporary mutations were restored after tests failed: bypassing status, negative withholding, cross-balance, missing FX, missing account, duplicate reversal, balance validation, base/raw balance invariants, four-place precision, same-currency rounding and the original row lock. The row-lock mutation caused both concurrent reversals to succeed. The missing-account mutation returned a zero line rather than the missing-account error; the test rejected it. These cover the principal independent guards; no claim is made that every possible failure path has a separate mutation.
