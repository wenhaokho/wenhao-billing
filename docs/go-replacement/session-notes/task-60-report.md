# Task 60 report

Added the manual recurring trigger endpoint, using the same persisted-admin and invoice row locks as template actions and the existing invoice-number allocation lock. It validates the schedule and cycle date, finds existing recurring children including VOID children by exact key or an equivalent parsed calendar date, recalculates totals, copies lines and invoice fields, applies hosting coverage and descriptions, and serializes the response before committing. The local-only injectable notifier runs for new drafts and a failure rolls back the transaction. No provider or real message is contacted. This callback is deliberately unexported and nil by default: production delivery still requires a transactional outbox, a durable dispatcher, retry policy, and per-recipient deduplication. It must not be connected to an external sender before that integration exists.

Unlike Python, which compares raw cycle-key strings and can duplicate a cycle when date spellings differ, the Go endpoint treats valid ISO calendar, compact and week-date spellings of the same day as one cycle. It retains the existing child metadata and stops for manual review when a same-template legacy key is malformed, incomplete, non-string, missing, or off-cycle and no recognized existing cycle matches. This is an intentional safety exception.
