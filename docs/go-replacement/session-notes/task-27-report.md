## Content-type review follow-up

Actual FastAPI HTTP differential on a separate isolated database now covers `application/json`, `application/vnd.billing+json`, uppercase JSON, missing content type, `text/plain`, `bad`, `application / json`, and `application/json; garbage`, each with valid JSON text and malformed JSON. It compares statuses and bodies, and verifies that rejected requests insert no vendor. Missing, non-JSON, and malformed media types return a body validation error; accepted JSON media types retain JSON parsing. Every nonempty non-JSON body is redacted rather than echoed, an intentional safety divergence from FastAPI. Non-JSON errors are resolved after authentication. A deferred database constraint trigger also forces commit failure after insertion and confirms a sanitized 500 and no committed row.

Additional mutations, all restored: removing the 1 MiB limit, raw-body password redaction, JSON validation password redaction, and commit-error handling each caused the integration test to fail. Removing deferred rollback caused the integration test to time out at 30 seconds because the unclosed transaction retained database locks; this tests the lock-leak consequence rather than independently proving every rollback path. The earlier initial-auth mutation was stopped by the independent locked role recheck after the helper had already written its 401/403 response.

Source review identified the same content-type mismatch in other routes: customer create/update (`customers_create.go`, `customers_update.go`), item create/update (`items_create.go`, `items_update.go`), chart-of-accounts create/update (`accounts_write.go`), login (`login_validation.go`), profile update (`users.go`), and handlers using `parseChangePasswordBody` (change-password, password recovery, and admin user writes). These Go handlers decode JSON without checking Content-Type, so otherwise valid JSON sent as text/plain or without a Content-Type can be treated as JSON instead of FastAPI's raw bytes. This finding is based on source inspection; those routes were not changed or differentially tested in this task.

After restoring all follow-up mutations, the prescribed full `go test -count=1 ./...` command above passed again (platform package: 139.861 seconds).
