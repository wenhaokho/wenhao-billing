# Intake extraction

This isolated package extracts candidates only; it does not receive webhooks, run OCR, access a database, or reconcile payments. Callers must treat `ErrInvalid` as a safe stop and handle OCR errors as failures. OCR is injected, must honor context cancellation and the provided output limit, and receives attachment content unchanged, matching the Python adapter's input contract; callers are responsible for decoding any provider encoding.

For valid, unambiguous inputs the fields match the generic Python webhook and email parsers. Deliberate stricter behavior: no implicit IDR, current date, UNKNOWN payer, empty external reference, or string coercion of non-string metadata; amounts must be positive, exactly representable by DECIMAL(19,4), and within its 15-integer-digit bound. Duplicate JSON fields, malformed dates, malformed grouping, and multiple email amount/reference matches are rejected. Currency syntax is checked but the package does not assert that a code is supported by the ledger. Inputs and OCR output are bounded to 1 MiB, and persisted text fields to 255 Unicode characters. Email amounts must occupy a complete structured line, optionally followed by a reference; prose and HTML are not parsed and require manual review. Each text source and OCR result is kept separate. References must occupy a complete structured line or follow the amount on its line. Raw HTML counts toward the input limit. The differential test runs Python with a lightweight stand-in for the reconciliation data class, without application dependencies.
